Featured: Household Shopping App

Architecture Overview

A mobile-first Next.js app for small families or shared homes. The app uses Server Components for initial data, Server Actions for mutations, and Supabase for auth, Postgres storage, row-level security, household membership, shopping sessions, item memory, and seed data.

Features

Create or join a household
Add, update, and clear shopping items
Group items into active shopping sessions
Use Supabase Auth and RLS policies
Share data safely between household members
Deploy as a Vercel-friendly full-stack app
Validate behaviour with lint and typecheck scripts
Keep the interface lightweight and mobile-first

What I Learned

  • Building authenticated flows with Supabase and Next.js App Router
  • Designing database tables around households, memberships, sessions, and reusable item memory
  • Using Server Actions for form-driven mutations without adding a custom API server
  • Thinking through permissions with row-level security rather than trusting the client
  • Keeping a production-style project maintainable with TypeScript, linting, and typechecking scripts
